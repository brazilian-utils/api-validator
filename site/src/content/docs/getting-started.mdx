Brazilian Utils is a family of libraries that validate, format and generate data specific to Brazil: CPF, CNPJ, CEP, license plates, phone numbers, boletos and more. There is one library per language, all maintained under the [brazilian-utils](https://github.com/brazilian-utils) organization.

This site documents all of them in one place.

## How the docs are organized

Every utility has **one page**, no matter how many languages implement it. Each page has the same sections:

<Steps>

1. **What it is and how it works.** The identifier, its rules, the algorithm and the regexes, when the utility has a long-form spec. This part, like everything below, comes from the shared contract in [api-validator](https://github.com/brazilian-utils/api-validator), not from any single library.

2. **Usage.** One section per operation (validate, format, generate…): its signature, which libraries implement it and whether they pass every case, the contract's description, one tab per language with the example, and the test cases. Pick JavaScript, Python, Go, Ruby, Rust, .NET or Erlang once and every page follows.

3. **Official sources.** The law, decree or agency document the rule comes from.

</Steps>

<Aside type="tip">
The language tabs only show *how to call* the library. The behaviour is the same everywhere because it is defined by the spec, not by any single implementation.
</Aside>

## What the libraries do not do

The libraries validate **structure**: length, allowed characters, check digits. They do not query government databases, so a "valid" CPF or CNPJ is a well-formed one, not necessarily one that exists or is active. Operations that call an external service (like looking up an address by CEP) say so explicitly on their tab.
